# チャットの書き込みと承認

対象: Desktop 内蔵チャット。採択: 2026-08-04〜08-22。承認方式の3段階は 2026-11-12 に決定した。
実行方式・認証・承認の現行方針は[内蔵 Pi runtime](pi-runtime.md)を優先する。

## 承認方式の選択

承認方式は3段階で、挙動は[内蔵 Pi runtime の表](pi-runtime.md#チャットの実行と承認)に従う。

- 新規のスレッドは全アカウントで「AIにより確認する（Auto review）」を初期選択する。審査はアプリに同梱した `pi-auto-review` が行う。
- 「すべての承認をスキップ（Full access）」は警告付きの明示選択のみで、自動では選ばない。明示選択に追加の確認 dialog は重ねない。
- 承認方式は Dahlia が保持し、Pi の session file には保存しない。開いているチャットで明示的に選んだ方式は保持する。
- 変更は次の MCP 変更操作の承認判定から効く。方式が不明なら「常に確認する」として扱う。
- 代理審査は追加のモデル呼び出しになり、手動承認の操作量は選択に応じて残る。

## MCP の承認

- 承認の対象は server・tool・整形済み引数全文・reason。表示を切り詰めた呼び出しは、方式によらず許可しない。
- 承認の prompt は合計 4 MiB、file change 50件、decision 16件、exec rule 50件に制限する。欠落・超過・未対応の要求は許可しない。
- snapshot は作成時に 4 MiB 以内に収め、raw の巨大 arguments を cache に保持しない。
- 承認 UI は bidi control を escaped で表示する。
- 承認は今回だけの許可として返す。セッション単位・永続の許可は受け付けず、拒否と同じに扱う。
- 拒否・停止は取り消しとする。チャット本文の「承認」は tool gate への応答の代用にならない。
- 承認 UI の command・path・reason を log や Sentry に送らない（[Telemetry policy](../../telemetry.md)）。

## 停止と未応答の承認

- 停止・取消は未応答の承認を cancel してから abort する。
- 未応答の承認は、利用者の判断・停止・実行の終了のいずれかで必ず解決し、二重に応答しない。
- transport 消失時だけ承認の登録を破棄する。

## 安全境界

- 承認 UI で sandbox の範囲（追加の filesystem・network 権限）を広げない。フルアクセスは別の明示選択で、Seatbelt は解除しない。
- 要約・未知の thread・旧 v1 approval・未対応の要求は fail-closed とする。不明な承認方式は「常に確認する」として扱う。

## 未適合・未検証

- 未確定: provider やモデル一覧による利用制限・事前確認を行わない規則（旧 Codex 版）が、Pi の承認方式の選択にも適用されるか。
