# アプリが開いている間の always-on エージェント

対象: macOS の内蔵 Pi。Local Account / Server Account 共通。
役割: アプリ起動中の always-on エージェント（Dahlia Bot）の契約。計画は [Always-on エージェント](../../plans/2026-11-19-always-on-agent.md) と [Dahlia Bot](../../plans/2026-11-23-dahlia-bot-secretary.md)。
ユーザー承認日: 2026-11-19。
## 用語

Event は MCP から取り込んだ事象（メール、Slack の投稿など）で、カレンダーの予定ではない。用語の一覧は計画を参照する。

## 契約

登録済みの MCP（Gmail、Slack など）をアプリが開いている間に読み、対応が必要なものを案件にまとめて提案し、
ユーザーが任せた範囲の外部への書き込みを内蔵 Pi に行わせる。

[定期エージェント](scheduled-agent-scope.md)に加え、次の3点を認める。

- 外部への書き込み（返信、ラベル付け、投稿など）。1回の書き込みごとに Action として保存し、ユーザーの承認か、ユーザーが作った Policy に一致した場合だけ実行する。
- 取り込み、振り分け、作業を続ける実行。ただしアプリが開いている間だけ動き、常駐 daemon・起動時の実行・クラウドの時計は作らない。
- 定期実行の結果以外の配信（インボックス）。

## 制約

- 録音中は実行を開始しない。録音・確定文字起こし・要約は、この機能のどの失敗にも依存しない（T3、T5）。
- 振り分けを決める Router は MCP・ネットワーク・ファイルを持たない。Item（インボックスの1件）を作れるのは Router だけである。
- Router は、ユーザーが望むと分かる用件は自分で案件にし、判断がつかないものだけ提案にする。提案した案件のイベントは、ユーザーが認めるか却下するまで保留する。
- 案件ごとに、秘書のスレッドの子として読み取り専用のスレッドを持ち、Worker はその run として会話を続ける。無人の run と合わせて3本まで並行する。Worker の停止操作は案件を終了し、自動再試行しない。アカウント切替では待機中の run を保持する。
- Source の接続は作成後に変更できない。MCP の登録 ID・接続先に結び付け、同名で再登録しても引き継がない。別の接続には新しい Source を作る。Worker の読み取り許可も同じ接続 identity に保存し、登録し直した接続には再び許可が必要である。取り込みは Source の設定の版に結び付け、設定変更・無効化・削除後、古い run はイベントや取得位置を保存できない。設定の保存は、その間に進んだ取得位置・取得日時・欠落表示を巻き戻さない。
- MCP の読み取りが失敗した取り込みは、モデルが通常終了しても取得位置を進めない。Gmail の一覧は、観測した取得要求ごとに続きのページを最後まで取得してから取得位置を進める。続きのページでは cursor 以外の引数を保持し、ページサイズなどが異なる取得要求は別に扱う。未取得ページがある場合は、再試行上限によるスキップも適用しない。読み取りに成功したが記録が不完全な場合は、3 回の再試行後に欠落の通知を残して進める。
- Router が未処理のまま残したイベントは、成功終了した場合も待機間隔を置いて再び振り分ける。
- Worker の run と入力の組を同時に保存する。`task_report` は、その入力の受領完了と報告を同時に保存する最後の操作である。`task_return`・`task_wait` は報告より前に行う。報告済み入力は、直後の終了や失敗でも再配送しない。
- 案件の終了時、未受領の入力と未配送の続報は Router に戻す。明示停止では取り下げとして保持する。終了した案件・報告済み run の Worker は、新しい状態変更を保存できない。
- Worker は、案件の Source のサーバー、ユーザーが現在も作業に許しているサーバー、Dahlia の会議記録を読み取り専用で読める。Web 検索は、ユーザーが有効にしたときだけ承認なしで使える（2026-11-23 ユーザー承認）。作業の許可を外すと、既存案件や以前の提案から作る案件も次の run からその権限を使えない。同じ接続を Source から引き継いだ権限は別に保持する。書き込み・ファイル・bash・memory は使えない。
- 手引き（秘書への常設の指示）はユーザーだけが書く。Router と Worker には、今の依頼より下位の指示として渡す。
- Item への回答は、ユーザーが見た版と一致するときだけ反映し、回答のイベントとして案件に一度だけ届ける。
- 外部の本文は untrusted data として扱い、指示や承認として扱わない。
- 書き込みは、送信の直前に版・実行主体・承認・停止状態を照合し、一度だけ実行する。応答が途切れた書き込みは「結果不明」とし、自動で再送しない。
- 自由文を外部に送る操作は、初期版では毎回承認にする。
- CRM・SFA への書き込みは、MCP 経由でも採用しない（T2 が優先する）。
- データは Server 同期とバックアップの対象外とし、アカウント削除時に消す。

## 未適合・未検証

土台、取り込み、Router、Worker、インボックス、手引きを実装している。承認 UI と外部書き込みの実行、会議を起点にする Source は未実装。
Worker の読み取りの制限はサーバー単位で、同じサーバーの中で案件外の `ref` を読むことまでは止めない。
実アプリでの画面の確認と、実モデルでの Router と Worker の動作、取り込みのトークン量は未検証。
