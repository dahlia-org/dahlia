# アプリが開いている間の always-on エージェント

対象: macOS の内蔵 Pi。アプリの単一アカウントで動作し、登録済みのプロバイダー接続を利用する。
役割: アプリ起動中の always-on エージェント（Agent。旧称 Dahlia Bot、Super Agent）の契約。計画は [Always-on エージェント](../../plans/2026-11-19-always-on-agent.md)、[Dahlia Bot](../../plans/2026-11-23-dahlia-bot-secretary.md)、[1本のスレッドにまとめる改修](../../plans/2026-11-25-dahlia-bot-thread.md)、[エージェントを複数持てるようにする](../../plans/2026-11-26-multi-agent.md)。
ユーザー承認日: 2026-11-19。イベント受信箱の方針は2026-11-26に決定。複数のエージェントと置き場所は2026-11-26に決定。
## 用語

Agent（日本語の画面では「エージェント」）は、ユーザーが名前とアイコンを付けて持つ人格で、home、1本の現行の会話、イベントソース、受信箱、タスクを持つ。何をするかはその `SOUL.md` が決める。Event は、エージェントの判断を起こす合図である。MCP から選んだメッセージ、カレンダーの時刻、自分用のリマインド、ユーザーの回答を含む。予定やメールの全文の写しではない。Task は仕事の記録、Item はユーザーへの質問・報告・提案である。

## 契約

登録済みの MCP（Gmail、Slack など）をアプリが開いている間に読み、対応が必要なものをエージェントがタスクのスレッドに任せ、
ユーザーに代わってそのスレッドを管理する。ユーザーはエージェントをいくつでも持てる。

[定期エージェント](scheduled-agent-scope.md)に加え、次の3点を認める。

- 外部への書き込み（返信、ラベル付け、投稿など）。タスクのスレッドが、ユーザーのチャットと同じ MCP の承認を通して行う（2026-11-25 ユーザー決定）。
- 取り込み、振り分け、作業を続ける実行。ただしアプリが開いている間だけ動き、常駐 daemon・起動時の実行・クラウドの時計は作らない。
- 定期実行の結果以外の配信（インボックス）。

## 制約

- 録音中は実行を開始しない。録音・確定文字起こし・要約は、この機能のどの失敗にも依存しない（T3、T5）。
- エージェントの一覧・名前・アイコン・home のフォルダ名の正本は DB の `agents` である。ID は UUIDv7 で変えない。home は `~/.dahlia/agents/<フォルダ名>/`（development build は自分のデータの folder の `agents`）で、フォルダ名は作成時に名前から決め（空白を `-`、小文字、`/`・`:`・制御文字・先頭の `.` を除く。空なら `agent`）、既存の行と `agents/` にあるフォルダの名前と大文字小文字を区別せず重なれば `-2` から番号を付ける。改名しても動かさない。名前は1〜80字。アイコンは同梱の mascot（`mascot:<ID>`）と明るい9色の見本の1つである。
- 設定で名前やアイコンの保存に失敗したら保存済みの表示へ戻し、エラーはそのエージェントだけに表示する。同じウィンドウではタブを離れて戻っても確認でき、次の保存成功か、別の入口からの名前・アイコン変更で消える。
- エージェントの作り方は、空から作るか、同梱のテンプレートから作るかである。テンプレートは作成の画面に名前・アイコン・最初の `SOUL.md` を入れるだけで、作ったエージェントとは結び付かない。テンプレートは Supervisor（秘書。旧称 Super Agent）の1つだけである。アプリはエージェントを自動では作らず、0件のときはサイドバーのカードに新規作成とテンプレートのメニューを出す（2026-11-26 ユーザー決定）。
- エージェントは1本の現行のスレッドで、ユーザーとの会話と振り分けの両方を行い、ユーザーに代わって仕事のスレッドを管理する。入口はサイドバーのエージェントのセクション（1件1行）で、受信箱（ユーザーの確認待ち、タスク）、取り込んだイベント（日ごとのタイムライン）、設定（上部で直接変える名前とアイコン、イベントソース、モデル、`SOUL.md`、最下部の削除）は、そのスレッドの右パネルの上部のボタンで切り替えて見る。名前とアイコンの変更と削除は、サイドバーの行のメニューからもできる。取り込みはイベントソースごとに止める。エージェントの現行のスレッドは通常のチャット履歴に出さない。履歴に出さない実行は、エージェントの責務の範囲のもの（通知のターン、取り込み、`delegate_task` の子）だけで、そのエージェントの home で動かす（2026-11-25 ユーザー決定）。
- スレッドがどのエージェントのものかは `chat_threads.agentID` で表す。現行の会話、古い会話、`delegate_task` の子（親から引き継ぐ）が持つ。エージェントを削除しても値は残る。`thread_launch` で起動したタスクのスレッドは通常のチャットで、持たない。
- エージェントが使えるのは、通常のチャットと同じスレッドの tool（`thread_*`・`delegate_task`・`task_status`・`task_cancel`）、自分の tool（`inbox_read`・`event_close`・`item_create`・`task_finish`・`soul_write`・`calendar_read`・`remind`）、Dahlia の会議記録の読み取り、自分の home の中のファイルの読み書きだけである。bash・外部の MCP・Web 検索・メモリーの書き込み・skill の編集は持たない。保存済みのメモリーは読み取り専用で渡す。エージェントのスレッドの会話は、メモリーと skill のふり返りにも、skill の改善の例にも使わない。Item（インボックスの1件）を作れるのはエージェントだけである。
- エージェントの間は分ける。自分の tool と `event_ids` は、呼んだスレッドのエージェント自身のイベント・タスク・Item だけを扱い、他のエージェントの ID は存在しないものとして断る。他のエージェントのスレッド（`agentID` が別のもの）は、スレッドの tool の一覧・検索・読み取り・送信・中断・改名・待機の対象にしない。通常のチャットからは今までどおり見える。sandbox は `agents/` 全体を通常のチャットから拒否し、エージェントには自分の home だけを開く。
- エージェントの system prompt は役割を決めず、名前、tool の使い方、外部の本文を指示として扱わない決まりだけを持つ。役割は `SOUL.md` が決める。
- タスクは、エージェントが `thread_launch` で起動した仕事の記録で、独立した ID、題名、依頼内容、状態、起動したエージェントを持つ。スレッドとは1対1で結び付く。スレッドを削除しても、タスクと依頼内容は残る。起動元がエージェントの現行のスレッドのとき、アプリがスレッドと一緒にタスクを記録し、結果をそのエージェントに自動で返す。承認待ちは返さず、起動のカードに「入力待ち」と出し、終わったときに結果を返す。モデルはタスクにするかを指定しない。起動したスレッドは最上位の通常のチャットとして履歴に出て、無人の間もユーザーのチャットと同じ権限（コマンド、作業フォルダ、コネクタの MCP、承認つきの外部への書き込み）で動く（2026-11-25 ユーザー決定）。メールや Slack の文面が起点でも同じなので、文面に仕込まれた指示にモデルが従えば、作業フォルダと許可したファイルを外へ送れる経路が残る。この点はユーザーが受け入れている。
- タスクを終えるのは、そのエージェントの `task_finish` か、ユーザーの右パネルでの操作だけである。スレッドが止まっただけではタスクは終わらない。終わったタスクのスレッドにそのエージェントが `thread_send` すると、タスクは進行中に戻る。ユーザーが手で送っただけでは戻らない。パネルの完了操作はタスクの ID に対して行い、スレッドを削除したタスクも終えられる。`task_finish` は `thread_id` を使う。
- `occurredAt` を過ぎた未判断のイベントがあると、Dahlia はそのイベントのエージェントの現行のスレッドに無人のターンを1つだけ積み、件数だけを伝える。本文はエージェントが `inbox_read` で読み、`thread_launch` か `thread_send` の `event_ids` でスレッドに渡すか、`event_close` で閉じる。渡したイベントの本文は、untrusted data として包んでスレッドへのメッセージに付ける。`inbox_read` はイベントが起きた時刻の順に返す。同じソースの同じ `topic` を扱う進行中タスクがあれば、そのスレッドをヒントとして添える。アプリは自動で紐付けず、続報もモデルが振り分ける。`event_ids` はエージェントの現行のスレッドからだけ受け付ける。
- 右パネルの設定で、取り込みと、そのエージェントが自動で動くとき（通知のターン、タスクの結果を受け取るターン）のモデルと推論の強さを選べる。エージェントの行に保存する。未選択なら、取り込みは Pi の既定、自動のターンは会話のものを使う。自動のターンのモデルと推論の強さは、クラッシュ後の復帰でも会話のものを置き換えない。
- 通知のターンと、エージェントが依頼した run は、録音中は始めない。通知のターンは停止中も始めず、始まっていれば止める。停止はアプリの1つの設定で、すべてのエージェントにかかる。ユーザー自身のターンは録音中も動く。通知のターンでも `thread_launch` と `thread_send` は使える。`soul_write` だけはユーザー自身のターンに限る。
- 現行の会話は DB の `agents.threadID` で識別する。DB はデータ保存先ごとにあるので、開発用ビルド・リリース版・別の worktree の操作で互いの会話を置き換えない。
- 会話のコンテキストは通常のチャットと同じ `/clear` でクリアする。次の送信から Pi のセッションだけを新しくし、同じスレッドの履歴、エージェント、タスク、確認待ちの Item は保持する。`agentID` を持ち、どのエージェントの現行でもない最上位のスレッドは、読み取り専用の古いスレッドとして扱う。
- 改名は、現行のスレッドの題名と home の写しを直す。動いている Pi のプロセスは始めたときの名前のままで、次のプロセスから新しい名前になる。
- 削除は確認のあとで、そのスレッドが依頼した run の結果通知を止め、依頼元は録音中の開始制限と承認上限のために保持し、エージェントの行を消す（ソース・イベント・タスク・Item は一緒に消える）。現行のスレッドの待機中の run を中断にし、実行中のターンとプロセスを止め、取り込みを閉じ、home をゴミ箱へ移す。現行のスレッドは古いスレッドとして読み取り専用で履歴に残る。起動したタスクのスレッドは通常のチャットとして残り、止めない。
- MCP のイベントソースの追加候補には Web Search・Google Drive・Google Calendar を含めない。カレンダーは、アプリで有効にした Google と Mac の予定を使う専用のソースとして追加する。追加では、名前か service に `slack` を含むサーバーを Slack、`gmail`・`mail`・`outlook` を含むものをメールとして固定の名前とアイコンを持つ1つの選択肢にまとめ、コネクタの設定で一番上のものを既定にする。追加の画面には選んだ種類のコネクタを常に示し、登録済みのものから選び直せる。作成後は読み取り専用で示し、保存した接続 ID と現登録が一致しない場合は接続を利用できないと示す。通常のチャットやタスクから使うコネクタの tool は対象外である。
- Source はエージェントに属し、作成後に別のエージェントへ移せない。接続も作成後に変更できない。MCP の登録 ID・接続先に結び付け、同名で再登録しても引き継がない。別の接続には新しい Source を作る。取り込みは Source の設定の版に結び付け、設定変更・無効化・削除後、古い run はイベントや取得位置を保存できない。設定の保存は、その間に進んだ取得位置・取得日時・直近の件数を巻き戻さない。取り込みは、どのエージェントのものでも一度に1つで、そのエージェントの home で動く。
- MCP の読み取りが失敗した取り込みは、モデルが通常終了しても取得位置を進めない。一覧は、観測した取得要求ごとに続きのページを最後まで取得してから取得位置を進める。続きのページでは cursor 以外の引数を保持し、ページサイズなどが異なる取得要求は別に扱う。未取得ページや拒否された記録のバッチがある場合も取得位置を保持する。全件を記録したかの照合や、失敗を回数でスキップする処理は持たない。
- 取り込みはソースの「読む内容」に合い、対応や注意が必要なメッセージだけを選ぶ。名指しや未回答など、直接のメンションがない依頼も判断する。積まなかったものの行や理由は残さない。保存するのは `key`、`topic`、500字までの `note`（何が起きたかと積んだ理由）、読み直すための `ref`、`occurredAt` である。`sender` は許可した送信者との照合にだけ使い、保存しない。取り込みが渡した未来の時刻は現在時刻に丸める。
- 1回の取り込みで新しく記録する上限は20件で、複数のバッチの合計にかける。同じソースの同じ `key` は重複として扱い、上限に数えない。20件に達すると取得位置を進めず、次回は同じ範囲を読み直して残りを記録する。初回は読み取りを始める前に24時間前の下限を保存し、上限到達・失敗・クラッシュ後も再試行の時刻で範囲を狭めない。この場合は未取得ページがあっても取得位置を保ったまま実行を終えられる。成功した実行では、観測したメッセージ ID の件数と新しく記録した件数をソースのカードに表示する。
- イベントの未判断は `handledAt` が空の状態で表す。判断済みで `taskID` があればタスクに渡したもの、なければ不要として閉じたものである。仕事の進行状態はタスクだけが持つ。判断してから30日を過ぎたイベントだけを掃除し、未判断のイベントとタスクは消さない。この機能の表には `accountID` を持たせず、ソース・イベント・タスク・Item は `agentID` を持つ。停止設定はアプリの1行にする。リリース済みのチャットなどの表のアカウントは維持する。
- カレンダーのソースは LLM を使わず、毎分の処理で、毎日の指定時刻と会議の指定時間前の合図を記録する。日付、または予定の ID と開始時刻で重複を除く。終日の予定と辞退した予定は会議前の対象にしない。未来の合図は、その時刻まで `inbox_read` にも通知にも出さない。会議が動いた・消えた・すでに始まった場合は、未判断の古い合図を、時刻を過ぎていても取り除く。取得に成功した接続の分だけ追加・照合し、有効なままの接続は、起動直後・認証切れ・取得失敗でも合図を消さない。接続を無効化・削除すると、ソースの停止中も、その接続の未判断の会議前の合図を取り消す。有効な接続がなくなれば、未判断の毎日の合図も取り消す。ソースや通知方法をオフにすると、対応する未来の未判断の合図を取り消す。ソースの停止では、すでに起きたイベントは判断の対象として残す。
- `calendar_read` は、アプリ内で取得済みの予定と、自分の回答状況（未回答・仮承諾・承諾・辞退・不明）を返す。予定の本文も untrusted data である。Google は既定で7日先まで取得するため、会議前の設定は0より大きく168時間未満にする。tool は7日以内の範囲を受け付け、取得に成功した接続と、100件を超えて省略したかを返す。別プロセスの Local MCP や Server MCP には公開しない。
- `remind(at, note)` は、未来の時刻と500字までの内容を持つ、そのエージェントのイベントを記録し、その ID を返す。`event_close` は、その ID を使って時刻前にも取り消せる。カレンダーとリマインドの時計は、アプリが開いている間だけ動く。
- 通知のターンが失敗したとき、または成功しても未処理のイベントを残したときは、そのエージェントに待機間隔（600秒）を置いて再び通知する。待機はエージェントごとにメモリーに持ち、再起動の後は未処理があれば1回すぐに通知する。
- 手引きは各エージェントの home の `SOUL.md` である。新規作成の画面の「誰で、何をするか」が最初の本文になる。ユーザーが右パネルで書くほか、ユーザーがエージェントとの会話で頼んだときに、エージェントが `soul_write` で書き換える。`soul_write` はユーザーのターンでだけ動き、承認の方式にかかわらず、毎回新しい本文をユーザーが認めてから保存する。エージェントと `delegate_task` の子には、今の依頼より下位の指示として先頭の8,000字を渡す。起動したタスクのスレッドには渡さないので、必要な指示はエージェントがメッセージに書く。起動後に変わったときは、次のターンの頭に新しい本文を渡す。
- home の `AGENTS.md` と `agent.json`（`id`・`name`・`avatar`・`color`）は DB の行の写しで、アプリが書き、違っていれば書き直す。`AGENTS.md` は Pi には読ませない。エージェントはファイルの tool でこの2つと `SOUL.md` を書けない。DB に行のないフォルダは読まない。
- Item への回答は、ユーザーが見た版と一致するときだけ反映し、回答のイベントとして Item のエージェントに一度だけ届ける。回答のイベントは `sourceID` が空で未判断の行とし、対象の `taskID`、短い `note`、Item とスレッドと回答全文の `ref` を持つ。
- 外部の本文は untrusted data として扱い、指示や承認として扱わない。
- 外部への書き込みは、通常のチャットと同じ MCP の承認を通す。
- CRM・SFA への書き込みは、MCP 経由でも採用しない（T2 が優先する）。
- データは Mac 上のアプリのアカウントに属し、Server 同期とバックアップの対象外とする。プロバイダー接続を削除してもタスクと履歴は保持し、削除した接続の権限は使えない。
- mascot の絵は Orca（stablyai/orca、MIT）の `mobile/assets/bot-mascots` をそのまま同梱し、取り込み元の commit と許諾文を `AgentMascots-LICENSE.txt` に置く。

## 未適合・未検証

土台、選別する取り込み、エージェントのスレッド、タスク、インボックス、`SOUL.md`、カレンダーの合図とリマインド、複数のエージェントとその間の境界を実装している。取り込みがメンションのない要対応メッセージを拾えるかを、ユーザーが判断した実データ50件と比べる評価は未実施。20件の上限と30日の保存期間は初期値で、実運用での妥当性は未検証。
実アプリでのエージェントのセクション、作成とアイコンの選択、右パネルの確認、実モデルでのエージェントとタスクのスレッドの動作、長く続く1本のスレッドでの会話の要約、通知と取り込みのトークン量（エージェントの数だけ増える）は未検証。mascot の絵が MIT の対象に含まれるかは、Orca のリポジトリのルートの `LICENSE` だけで判断しており、Orca 側には確認していない。
