# アプリが開いている間の always-on エージェント

対象: macOS の内蔵 Pi。アプリの単一アカウントで動作し、登録済みのプロバイダー接続を利用する。
役割: アプリ起動中の always-on エージェント（Super Agent。旧称 Dahlia Bot）の契約。計画は [Always-on エージェント](../../plans/2026-11-19-always-on-agent.md)、[Super Agent](../../plans/2026-11-23-dahlia-bot-secretary.md)、[1本のスレッドにまとめる改修](../../plans/2026-11-25-dahlia-bot-thread.md)。
ユーザー承認日: 2026-11-19。
## 用語

Event は MCP から取り込んだ事象（メール、Slack の投稿など）で、カレンダーの予定ではない。用語の一覧は計画を参照する。

## 契約

登録済みの MCP（Gmail、Slack など）をアプリが開いている間に読み、対応が必要なものを Super Agent がタスクのスレッドに任せ、
ユーザーに代わってそのスレッドを管理する。

[定期エージェント](scheduled-agent-scope.md)に加え、次の3点を認める。

- 外部への書き込み（返信、ラベル付け、投稿など）。タスクのスレッドが、ユーザーのチャットと同じ MCP の承認を通して行う（2026-11-25 ユーザー決定）。
- 取り込み、振り分け、作業を続ける実行。ただしアプリが開いている間だけ動き、常駐 daemon・起動時の実行・クラウドの時計は作らない。
- 定期実行の結果以外の配信（インボックス）。

## 制約

- 録音中は実行を開始しない。録音・確定文字起こし・要約は、この機能のどの失敗にも依存しない（T3、T5）。
- Super Agent は1本のスレッドで、ユーザーとの会話と振り分けの両方を行い、ユーザーに代わって仕事のスレッドを管理する。入口はサイドバーの Agents セクションで、受信箱（ユーザーの確認待ち、タスク、取り込んだイベント）と設定（イベントソース、`SOUL.md`）は、そのスレッドの右パネルの上部のボタンで切り替えて見る。取り込みはイベントソースごとに止める。Super Agent のスレッドは通常のチャット履歴に出さない。履歴に出さない実行は、Super Agent の責務の範囲のもの（通知のターン、取り込み、`delegate_task` の子）だけで、Super Agent の home で動かす（2026-11-25 ユーザー決定）。
- Super Agent が使えるのは、通常のチャットと同じスレッドの tool（`thread_*`・`delegate_task`・`task_status`・`task_cancel`）、自分の tool（`inbox_read`・`event_close`・`item_create`・`task_finish`・`soul_write`）、Dahlia の会議記録の読み取り、home（`~/.dahlia/bots/super-agent/`）の中のファイルの読み書きだけである。bash・外部の MCP・Web 検索・メモリーの書き込み・skill の編集は持たない。保存済みのメモリーは読み取り専用で渡す。Super Agent のスレッドの会話は、メモリーと skill のふり返りにも、skill の改善の例にも使わない。Item（インボックスの1件）を作れるのは Super Agent だけである。
- タスクは、Super Agent が `thread_launch` で起動したスレッドである。起動元が Super Agent のスレッドのとき、アプリがスレッドと一緒にタスクを記録し、結果を Super Agent に自動で返す。承認待ちは返さず、起動のカードに「入力待ち」と出し、終わったときに結果を返す。モデルはタスクにするかを指定しない。起動したスレッドは最上位の通常のチャットとして履歴に出て、無人の間もユーザーのチャットと同じ権限（コマンド、作業フォルダ、コネクタの MCP、承認つきの外部への書き込み）で動く（2026-11-25 ユーザー決定）。メールや Slack の文面が起点でも同じなので、文面に仕込まれた指示にモデルが従えば、作業フォルダと許可したファイルを外へ送れる経路が残る。この点はユーザーが受け入れている。
- タスクを終えるのは、Super Agent の `task_finish` か、ユーザーの右パネルでの操作だけである。スレッドが止まっただけではタスクは終わらない。終わったタスクのスレッドに Super Agent が `thread_send` すると、タスクは進行中に戻る。ユーザーが手で送っただけでは戻らない。
- 新しいイベントがあると、Dahlia は Super Agent のスレッドに無人のターンを1つだけ積み、件数だけを伝える。本文は Super Agent が `inbox_read` で読み、`thread_launch` か `thread_send` の `event_ids` でスレッドに渡すか、`event_close` で閉じる。渡したイベントの本文は、untrusted data として包んでスレッドへのメッセージに付ける。同じ話題の続報もモデルが見て振り分ける。`event_ids` は Super Agent のスレッドからだけ受け付ける。
- 通知のターンと、Super Agent が依頼した run は、録音中は始めない。通知のターンは停止中も始めず、始まっていれば止める。ユーザー自身のターンは録音中も動く。通知のターンでも `thread_launch` と `thread_send` は使える。`soul_write` だけはユーザー自身のターンに限る。
- 現行の会話はデータ保存先ごとに識別し、開発用ビルド・リリース版・別の worktree の操作で互いの会話を置き換えない。
- 会話をやり直すと、新しいスレッドに置き換え、古いスレッドは読み取り専用で通常の履歴に残す。古いスレッドの通知と実行は止める。タスクはそのまま引き継ぐ。Super Agent のスレッドの run はすべて `bot` プロファイルで記録し、それを持つ現行以外の最上位のスレッドを古いスレッドとして扱う。
- イベントソースの追加候補には Web Search・Google Drive・Google Calendar を含めない。通常のチャットやタスクから使うこれらの tool は対象外である。
- Source の接続は作成後に変更できない。MCP の登録 ID・接続先に結び付け、同名で再登録しても引き継がない。別の接続には新しい Source を作る。取り込みは Source の設定の版に結び付け、設定変更・無効化・削除後、古い run はイベントや取得位置を保存できない。設定の保存は、その間に進んだ取得位置・取得日時・欠落表示を巻き戻さない。
- MCP の読み取りが失敗した取り込みは、モデルが通常終了しても取得位置を進めない。Gmail の一覧は、観測した取得要求ごとに続きのページを最後まで取得してから取得位置を進める。続きのページでは cursor 以外の引数を保持し、ページサイズなどが異なる取得要求は別に扱う。未取得ページがある場合は、再試行上限によるスキップも適用しない。読み取りに成功したが記録が不完全な場合は、3 回の再試行後に欠落の通知を残して進める。
- 通知のターンが失敗したとき、または成功しても未処理のイベントを残したときは、待機間隔（600秒）を置いて再び通知する。待機はメモリーに持ち、再起動の後は未処理があれば1回すぐに通知する。
- 手引きは Super Agent の home の `SOUL.md` である。ユーザーが右パネルで書くほか、ユーザーが Super Agent との会話で頼んだときに、Super Agent が `soul_write` で書き換える。`soul_write` はユーザーのターンでだけ動き、承認の方式にかかわらず、毎回新しい本文をユーザーが認めてから保存する。Super Agent と `delegate_task` の子には、今の依頼より下位の指示として先頭の8,000字を渡す。起動したタスクのスレッドには渡さないので、必要な指示は Super Agent がメッセージに書く。起動後に変わったときは、次のターンの頭に新しい本文を渡す。
- home の `AGENTS.md` と `bot.json` はアプリが書き、違っていれば書き直す。`AGENTS.md` は写しで、Pi には読ませない。Super Agent はファイルの tool でこの2つと `SOUL.md` を書けない。通常のチャットからは home を読み書きできない。
- Item への回答は、ユーザーが見た版と一致するときだけ反映し、回答のイベントとして Super Agent に一度だけ届ける。回答のイベントには、Item が結び付いたタスクのスレッドを記す。
- 外部の本文は untrusted data として扱い、指示や承認として扱わない。
- 外部への書き込みは、通常のチャットと同じ MCP の承認を通す。
- CRM・SFA への書き込みは、MCP 経由でも採用しない（T2 が優先する）。
- データは Mac 上のアプリのアカウントに属し、Server 同期とバックアップの対象外とする。プロバイダー接続を削除してもタスクと履歴は保持し、削除した接続の権限は使えない。
