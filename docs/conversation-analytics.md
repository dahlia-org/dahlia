# 会話分析（ベータ）

会話分析は、ミーティングの確定済み文字起こしから、話す速度、発話バランス、会話の密度、
同時発話を俯瞰するダッシュボードです。設定の「詳細」→「ベータ機能」で「会話分析」を有効にすると、
ミーティング詳細の末尾に「会話分析」タブ（`⌘5`）が表示されます。録音中のミーティングは、
録音停止と文字起こしの確定後に分析できます。

## 音源の扱い

- マイク音声（`mic`）を「自分」、システム音声（`system`）を「相手側」として表示します。
- システム音声には複数の参加者や他アプリの音声が含まれる場合があります。話者ダイアライゼーションではありません。
- 確定済みの原文セグメントだけを対象とし、翻訳文と音源を判定できないセグメントは集計しません。
- 正規化文字数は、原文から空白と改行を除いた Swift `Character` 数です。言語や文字体系が異なる音源同士の
  文字/分は、直接的な良否比較には使えません。

## 指標

SQLite には割合や速度ではなく、録音時間、集計済みの発話時間、文字数、確定セグメント数を保存します。
ダッシュボードでは次の派生値を表示時に計算します。

| 指標 | 定義 |
| --- | --- |
| 発話速度 | `normalizedCharacterCount / sourceSpeechDuration × 60`（文字/分） |
| 発話比率 | `sourceSpeechDuration / Σ sourceSpeechDuration` |
| 会話占有率 | `unionSpeechDuration / recordingDuration` |
| オーバーラップ率 | `overlapDuration / unionSpeechDuration` |
| 最長連続発話 | 同一音源の発話を3秒以内の間隔で結合した、最長区間の開始から終了までの時間 |

分母が 0 の場合は 0% とみなさず「算出不可」と表示します。同一音源内で重なる区間、または間隔が
1.5 秒以内の区間を先に結合し、その間を連続した発話として扱います。結合後の音源別区間から発話時間、
発話速度、発話比率を計算し、マイクとシステム音声の union から会話占有率、両音源の intersection から
オーバーラップ率を求めます。同じ結合済み区間を「会話の流れ」タイムラインにも表示します。
最長連続発話だけはこの1.5秒結合とは分離し、確定済みのrawセグメントから同一音源の区間を3秒以内の
間隔で結合します。間に相手側の発話があっても結合を分割せず、挟まれた無音時間を含む開始から終了までを
継続時間として、会議全体で最長の話者・時間帯とともに表示します。
「発話ペースの推移」は、測定可能な各セグメントの文字数をその発話区間へ比例配分し、間を埋めた
音源別発話時間で割って算出します。最小単位は 1 分で、長時間会議では音源ごとに最大 60 点となるよう
時間幅を自動的に広げます。発話が無い時間帯は 0 文字/分とはみなさず、折れ線を分断します。
時間を計測できないセグメントは位置を決められないため、この推移グラフから除外します。
長時間会議で区間数が多い場合、指標と重なり回数は正確な値を保ったまま、タイムライン表示だけを
音源ごとに最大 512 区間の時間バケットへ集約します。
終了時刻が無い、逆転している、または録音区間へ収めると長さが 0 になるセグメントは、文字数と
セグメント数には含めますが、時間指標から除外します。この場合、文字/分は概算として表示します。

## 音声（プロソディ）分析

バッチ文字起こしでは、保存音声からセグメントごとの相対音量、中央ピッチ、activity gate 通過率、
ピッチ分布の幅を補助特徴として保存します。リアルタイム文字起こしと、音声特徴の保存より前に作成された
旧ミーティングには、このデータがありません。5件以上を計測できた録音セッションに属するセグメントが
音源ごとに合計10件以上ある場合、ダッシュボードに次の指標を表示します。

| 指標 | 定義 |
| --- | --- |
| 会話の盛り上がり | セッション内の相対音量と音源内の相対ピッチを robust z-score に変換し、`0.6 × 音量 + 0.4 × ピッチ`で合成。ピッチ不足時は音量のみ |
| ホットスポット | 平滑化した盛り上がりが `+1.5` 以上で、15秒以内の間隔でまとまる区間。高スコア区間の被覆時間が合計10秒以上のものを最大8件表示 |
| 声の抑揚 | ピッチ変動（半音）と音量変動（dB）を独立した3段階で表示 |
| 声の高さの同調 | 時間バケットごとのマイクとシステム音声の中央ピッチ距離を半音で表し、前半1/3と後半1/3を比較する実験的指標 |
| 声のエネルギー推移 | 録音セッション内の基準音量からの相対dBを時間バケット化し、`-2 dB / 10分`以下の回帰傾きを低下傾向として表示 |

音量はOS処理、デバイス、ゲインの影響を受けるため、`source × recording session` ごとに median とMADを
求め、その基準からの相対値だけを使います。セッション内の計測可能セグメントが5件未満の場合、その
セッションの音量分析は行いません。マイクとシステム音声の絶対音量、および異なる録音セッションの
絶対音量は比較しません。チャートは長時間会議でも音源ごとに最大60点へ集約します。

ピッチはHzを `12 × log2(Hz / 100)` で半音へ変換します。version 1 の `audioVoicedFrameRatio` は
ピッチ検出率ではなくactivity gate通過率なので、ピッチの有効判定には使いません。代わりに、分析器が
4つ以上のピッチ検出窓から算出した `pitchSpreadHertz != nil` を弱い代理条件として使います。厳密な
ピッチ信頼度には、将来のfeature versionでピッチ検出フレーム比率を追加する必要があります。

抑揚のピッチ軸は、セグメント間の中央ピッチIQRと、セグメント内の
`12 × log2((medianPitch + pitchSpread) / medianPitch)` の中央値の大きい方です。1.5半音未満を「単調」、
1.5〜3.0半音を「標準」、3.0半音超を「豊か」とします。音量軸はセッションごとの音量IQRの中央値で、
2.0dB未満を「一定」、2.0〜5.0dBを「標準」、5.0dB超を「ダイナミック」とします。これらの閾値は
コーチング表示のためのヒューリスティックであり、感情や心理状態を断定しません。システム音声には複数話者が
含まれる場合があるため、同調指標は「相手側全体」との距離として扱います。

音声分析結果は表示時にSQLiteの文字起こしセグメントから再生成し、会話分析の永続レコードやfingerprintには
含めません。音声特徴だけが更新された場合も、キャッシュヒット時のtimeline projectionから最新結果を作ります。
LLM要約への音声分析の組み込みは現時点のスコープ外です。

## 更新と旧データ

分析値は既存ミーティングを起動時に一括変換せず、タブを初めて開いたときに作成します。録音停止、
バッチ文字起こし、再文字起こしの完了後にもバックグラウンドで更新します。入力 fingerprint は、
指標に影響する録音セッションと確定文字起こしだけから作るため、会議名、説明、タグ、翻訳、要約の変更では
再集計しません。

録音セッションとの関連が無い旧セグメントは、通常の録音セッションとは重ならない独立タイムラインへ
配置します。旧セグメント同士の同時発話は維持され、推定区間を含む実効録音時間を会話占有率の分母に使います。
画面には「推定タイムライン」の注記が表示されます。
この分析は再生成可能な補助データであり、録音音声と確定文字起こしの保存成功を妨げません。
