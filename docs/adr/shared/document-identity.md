# Workspace に属する独立した Document

採択: 2026-09-29。ユーザーがサイド会話で承認し、進行中の Documents 実装への反映を依頼した決定。

## 置換する決定

[Documents](documents.md) の「文書 UUID は会議 UUID と同じ」「meeting_id 全体が一意」を置き換える。Document は Workspace に属する独立した実体で、独立して発行した UUIDv7、任意の meeting_id、kind（notes / summary / general）、自身の title を持つ。1文書が属する会議は最大1件であり、関連付けテーブルは設けない。会議に属さない文書も認可・保存・同期・バックアップの対象になる。

会議と文書の Workspace 一致は複合外部キーで保証する。Notes のみ、会議ごとに1件という部分一意制約を設ける。notes は会議への関連を必須とし、summary / general は会議への関連を任意とする。Workspace の認可が第一の境界で、会議がある場合は会議の有効性も検査する。

## 初期化とクライアント

Notes の取得と作成は会議＋用途で解決する。作成は Workspace の既存ロックと DB 一意制約で直列化し、複数端末の提案 ID が異なっても、先に確定した文書を返す。画面を開くだけでは作成しない。同期・復元記録・presence は応答の文書 ID を使う。

Desktop のオフライン文書は独立 ID で作成し、Server で確定した Notes ID が異なる場合、短い transaction で ID と従属記録を関連付け直す。Yjs の状態・未送信差分・復元記録は保持する。公開前の旧 Notes は従来どおり明示操作を必要とし、既に編集された共有 Notes には自動結合しない。

## ライフサイクルと要約

会議に属する全用途の文書は会議の削除・復元・移管に従い、会議のない文書は Workspace に従う。バックアップでの文書 ID と会議 ID は別々に再割り当てする。未公開コピーも所属・用途・タイトルを保持する。要約入力は対象会議の kind=notes のみを選ぶ。生成ジョブの入力 snapshot・実行履歴は Document と分離する。Workspace の空判定と reset は会議未関連の文書も含める。Desktop は文書一覧にない共有キャッシュを文書 API でも確認し、不在が確定した場合に整理する。未送信差分・復元記録は同じ transaction 内で非公開の復元用記録に保全し、Server 一覧に出ない非公開コピーを削除しない。Local→Server 移管では会議未関連の非公開コピーも移管先に引き継ぐ。

配布済み Desktop migration は維持し、既に登録した v47 も変更せず v48 で更新する。旧 ID の値が偶然会議 ID と同じ既存行はそのまま有効とし、破壊的な再採番は行わない。Server は未リリース baseline を Drizzle から再生成する。既存 DB の削除・履歴書換えは行わない。

汎用文書一覧・Summary エディタなど新しい画面は今回追加しない。従来 ADR の公開、保全、CRDT、暗号化、オフライン、依存、録音と独立した同期の契約を維持する。

共有 Workspace 間の移管では、会議未関連の文書 ID も移管 receipt に保存する。relocations API は通常の同期 entity と別の documents 配列で現在の所属を返し、移管先の現行認可を検査する。Desktop は旧所属の 404 を削除と扱う前にこの情報を確認し、未取得の移管先 Workspace を登録して、同じ接続の文書と未送信差分を transaction 内で関連付け直す。本文をドメイン transaction キューへ送ることはしない。

移管先の現行 role・personal user は、既に端末に Workspace がある場合も relocation 応答から反映する。既存の移管先が初期同期・復元途中の場合は移管を延期し、同期確認状態を変更しない。viewer になった場合、未送信編集と復元記録を端末に保持し、書き込みは止めて文書の受信を続ける。権限復旧後は未送信分を再送できる。未送信分が残る viewer の要約前 flush は失敗させ、省略した入力で開始しない。
