# ADR-0042: バッチ録音へ現在の保存期間を遡及適用する

- Status: Accepted
- Date: 2026-08-26
- Amends: ADR-0004

## Context

バッチ文字起こしは従来、録音セッションごとに「文字起こし成功後に削除」または「アプリ内に保持」を固定していた。
削除を選んだまま誤った言語で文字起こしが成功すると、再文字起こしに必要な音声が直ちに失われる。

## Decision

- バッチ録音は既定で3日間保持し、保存期間を無期限、1日、3日、7日、14日から選べるようにする。
- 現在の設定を、`recording_sessions.endedAt` と `batchCompletedAt` の遅い方から計算し、期限を過ぎた音声を既存のpurge state machineで削除する。
- 設定は既存録音にも遡及適用する。ファイルやセッションへ個別のTTLまたは保持例外を保存しない。
- 文字起こし成功済みで、再文字起こし中ではなく、failed segmentを持たないセッションだけを自動削除する。
- 旧「文字起こし後も音声を保持」を選択していたユーザーは無期限へ移行する。それ以外は3日を既定とし、即時削除の選択肢は提供しない。
- ユーザーが保存期間を選択するまでは既定値をUserDefaultsへ書かず、未選択状態を維持する。
- 保存期間を短縮する前に、期限超過した既存録音が直ちに削除され得ることを確認する。purge開始後の設定変更では音声を復元しない。
- リアルタイム文字起こしは音声を保存しないため、この設定の対象外とする。

これはADR-0004の「保持方針をセッションへ固定し、現在のUserDefaultsで過去データを再分類しない」という判断を置き換える。
immutable segment、失敗時の保持、purge intentの永続化、active／ambiguousな音声の削除拒否は維持する。

## Consequences

- 誤った言語で文字起こししても、保存期間内は音声から再実行できる。
- 保存期間の短縮は複数の既存録音を一度に削除し得る。
- 特定の録音だけを永久保持する操作はない。必要になった場合は別の明示的な例外機能として設計する。
- 既存schemaの `retainAudioAfterBatch`、`audioRetentionPolicy`、`retentionExpiresAt` はmigration履歴として残るが、runtimeは参照しない。
