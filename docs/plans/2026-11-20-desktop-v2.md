# Desktop v2（Electron、独立実装）

対象: 新規パッケージ `apps/desktop-v2`。Dahlia for macOS（`apps/macos`）、Server、`packages/ui`、既存の Electron アルファ（`apps/desktop`）は変更しない。
状態: 2026-11-20、ユーザーの実装依頼により推奨案（案 A、`apps/desktop-v2`、`dahlia-v2`）で実装済み。自動検証済み。実 Workspace でのサインイン・要約と、実機での録音（特にシステム音声）は未確認。Tenet との不一致は [Desktop v2 ADR](../adr/desktop/electron-v2.md) に記録し、ユーザーの確認待ち。現在の構成は [Desktop v2 README](../../apps/desktop-v2/README.md)。
前提: ユーザー指示により、Server と共有する現行 Electron 実装は参照しない。Databricks 認証のみ、独立 DB、録音と要約が必須、ライブ文字起こし・字幕・AI チャットは対象外、見た目は Swift 版に寄せる。

## 完了条件

署名なしのローカルビルドで、次の一連が Mac 1 台で通ること。

1. Databricks Workspace URL を入力し、ブラウザでサインインできる。再起動後もサインイン状態が続く。
2. 録音を開始・停止でき、マイクとシステム音声が別ファイルで保存される。
3. 停止後に文字起こしが自動で走り、文字起こしタブに時刻順で表示される。
4. 続けて要約が生成され、要約タブに表示される。失敗時は理由と再試行が表示される。
5. 録音中にアプリが落ちても、落ちる直前までの音声が残り、次回起動時に文字起こしから再開できる。
6. `pnpm --filter @dahlia-ai/desktop-v2 check`（lint・型・テスト・ビルド）が通る。

## 先に決めてほしいこと

実装方針が大きく変わる順に並べる。各項目の先頭が推奨案。

### 1. 文字起こしの実行方法

ライブ文字起こしは不要だが、要約の入力として録音後の文字起こしは必要になる。Electron からは Apple Speech を直接呼べない。

| 案 | 内容 | 利点 | 欠点 |
| --- | --- | --- | --- |
| A（推奨） | 小さな Swift 製 CLI `dahlia-transcribe` を同梱し、Apple Speech（`SpeechAnalyzer` + `SpeechTranscriber`）で録音ファイルを処理する | 音声が Mac の外に出ない。現行の品質と [T5](../../PRODUCT.md#t5-中核はスタンドアローンで完結させる) を保つ。オフラインで動く | macOS 専用。Swift のビルドと同梱が要る。言語は手動選択（WhisperKit の自動判定は移さない） |
| B | AI Gateway の Gemini へ音声を送り、文字起こしを得る | ネイティブコードが不要。言語を自動判定できる | 音声をクラウドへ送るため、PRODUCT.md の「Desktop で開始した文字起こしのクラウド処理」（Out of scope）に反する。採用には tenet を更新する ADR の承認が先に必要。長時間録音は分割が要る |

案 A の CLI は新規に書く（約 200 行の見込み）。現行の文字起こしコードは `Dahlia` 実行ターゲットの中にあり、ライブラリとして切り出されていないため再利用できない。呼び出し方の調査結果と設計は「[文字起こし](#文字起こし案-a)」に書いた。

### 2. Tenet との不一致（報告）

v2 の前提は現行の tenet と次の点で合わない。PRODUCT.md は書き換えず、v2 用の ADR（`docs/adr/desktop/electron-v2.md`）で承認を得る想定。

- **T3 の録音保全**: [録音ストレージ ADR](../adr/desktop/recording-storage.md) の 60 秒 segment・状態機械・SHA-256 検証は移さない。追記のみのヘッダーなし PCM を 5 秒間隔のタイマーで fsync する。クラッシュ時には capture・IPC の未保存バッファも失われるため、損失時間の上限は保証しない。通常停止・終了時は残りの音声を送信してからファイルを閉じ、保存失敗や入力切断は録音エラーとして表示する。
- **T1 / T4 の MCP**: v2 の最小版は MCP を持たない。

## 構成

```
apps/desktop-v2/
  src/main/        main process: 認証、DB、録音ファイル、文字起こし、要約
  src/preload/     renderer に公開する操作（下記の一覧のみ）
  src/renderer/    React の画面
  native/          dahlia-transcribe（独立した SwiftPM パッケージ、依存なし。案 A の場合）
  tests/
```

ビルド道具は `apps/desktop` と同じ版をそのまま使う（Electron 44.4.5、Vite、tsup、React 19、Tailwind 4、vitest、eslint）。実行時の依存は追加しない。DB は Node 標準の `node:sqlite` を使う。`@dahlia-ai/ui` は import しない。

Electron の安全設定は `nodeIntegration: false`、`contextIsolation: true`、`sandbox: true` とし、token は main process の外に出さない。preload が公開する操作は次のとおり。main process は送信元がメインウィンドウであることと入力を検証する。

- `auth`: `signIn(workspaceURL)`、`cancelSignIn()`、`signOut()`、`state()`
- `meetings`: `list()`、`get(id)`、`rename(id, name)`、`delete(id)`、変更通知の購読
- `recording`: `start()`、`append(source, chunk)`、`stop()`
- `processing`: `retranscribe(meetingId)`、`summarize(meetingId)`
- `settings`: `get()`、`set(patch)`、`models()`

## 認証

Swift 版の [`DatabricksOAuthService.swift`](../../apps/macos/Sources/Dahlia/Services/DatabricksOAuthService.swift) と同じ契約を TypeScript で書く（[OAuth ADR](../adr/desktop/accounts.md#chatgpt-と-databricks-workspace-oauth)）。

- 認証方式は Databricks のみ。T5 に従い、初回・サインアウト後も録音・文字起こし・閲覧・設定は使える。要約の生成・再試行またはアカウントメニューからサインイン画面を開く。画面は閉じてローカル操作へ戻れる。
- public client `databricks-cli`、Authorization Code + PKCE（S256、verifier 64 バイト）、state 検証。
- `{workspace}/oidc/.well-known/oauth-authorization-server` を取得し、https かつ同一 origin の endpoint だけを使う。取得できなければ `/oidc/v1/authorize` と `/oidc/v1/token` を使う。
- システムブラウザで開き、`http://localhost:8020`〜`8040` のうち待受できた最初のポートで受ける。待受は 300 秒で終了する。
- 利用者のメールは `GET /api/2.0/preview/scim/v2/Me` の `userName` から取る。
- credential は Electron の `safeStorage`（macOS Keychain の鍵で暗号化）で暗号化したファイルに保存する。refresh が失敗したら再サインインを案内する。同時 refresh は 1 回にまとめ、新しい credential は保存に成功してから使う。
- サインアウトは local credential を消す。DB と録音は残す。
- token、code、callback の query はログと表示用エラーに含めない。

`node:sqlite`、WAL。`PRAGMA user_version` で版を管理する。

| テーブル | 主な列 |
| --- | --- |
| `meetings` | `id`、`name`、`description`、`created_at`、`updated_at` |
| `recordings` | `id`、`meeting_id`、`started_at`、`ended_at`、`locale`、`status`（`recording` / `recorded` / `transcribing` / `transcribed` / `failed`）、`error` |
| `transcript_segments` | `id`、`meeting_id`、`recording_id`、`source`（`mic` / `system`）、`start_ms`、`end_ms`、`text` |

音声ファイルのパスは `recordings/<meeting_id>/<recording_id>/{mic,system}.pcm` と ID から導出し、DB には保存しない。

## 録音

- マイク: `getUserMedia`（`echoCancellation: true`）。
- システム音声: `setDisplayMediaRequestHandler` で `audio: "loopback"` を返し、`getDisplayMedia` の映像トラックはすぐに止める。Electron 39 以降は macOS 14.2 以降で CoreAudio Tap を使うため、アプリの Info.plist に `NSAudioCaptureUsageDescription` が要る。許可がない場合もエラーにならず無音のトラックが返るので、システム音声が無音のまま続いたら録音状況バーに警告を出す。
- 各ストリームを `AudioWorklet` で 16 kHz・モノラル・Int16 に変換し、1 秒ごとに main process へ送る。main process はヘッダーなしの `.pcm` に追記し、5 秒ごとに fsync する。ヘッダーがないため、途中で落ちてもそこまでの音声が読める。
- 録音中はウィンドウを閉じても隠すだけにし、終了時は確認する。`backgroundThrottling` は無効にする。
- 起動時に `status = recording` の行があれば、ファイル長から終了時刻を決めて `recorded` にし、文字起こしへ進める。
- サイドバー下部に経過時間と音源ごとの入力レベルを表示する。
- 録音開始は token の状態を確認しない。

## 文字起こし（案 A）

Electron と Apple の公式ドキュメント、および同じ API を使う公開 CLI（yap）を調べた結果を反映した。出典は末尾にまとめた。

### 呼び出し方: 別プロセスの CLI にする

Electron から Swift を使う方法は 2 つある。v2 は CLI を採る。

| 方法 | 内容 | 判断 |
| --- | --- | --- |
| CLI を子プロセスで実行（採用） | Swift の実行ファイルを `child_process.spawn` で起動し、標準出力で結果を受ける | 文字起こしが落ちても止まっても、録音を持つ main process は影響を受けない。止まったらプロセスを終了させれば回復できる。追加の依存がない |
| ネイティブアドオン | Electron 公式の手順。Swift → Objective-C → Objective-C++ → Node-API の 4 層を `node-gyp` でビルドする | 層とビルド道具（`node-addon-api`、`node-gyp`）が増える。アドオン内の異常終了は main process ごと落とし、録音を巻き込む。採らない |

Apple は別プロセスの実行に XPC Service も挙げているが、Electron からは接続の橋渡しが別途必要になるため使わない。

### CLI の仕様

`native/` に独立した SwiftPM パッケージとして置く（Swift 6.2、macOS 26 以降、依存なし）。ルートの `Package.swift` には足さない。

```
dahlia-transcribe locales
dahlia-transcribe transcribe --locale ja-JP --sample-rate 16000 <file.pcm>
```

- `locales` は `SpeechTranscriber.supportedLocales` を返す。設定画面の言語一覧に使う。
- 標準出力は JSON Lines。`{"type":"asset","fraction":0.4}`（モデル取得の進み）、`{"type":"progress","processed_ms":…}`、`{"type":"segment","start_ms":…,"end_ms":…,"text":…}`、最後に `{"type":"done"}`。
- 失敗は終了コードと `{"type":"error","code":…}` で返す。code は `unsupported_locale` / `assets_unavailable` / `invalid_audio` / `failed`。標準エラーには本文と音声由来の情報を出さない。

Swift 側の実装は Apple の手順に沿う。

1. `SpeechTranscriber.isAvailable` と `supportedLocale(equivalentTo:)` で対応を確かめる。非対応なら `unsupported_locale`。
2. `AssetInventory.status(forModules:)` が未インストールなら `assetInstallationRequest(supporting:)` → `downloadAndInstall()`。モデルは Apple のサーバーから取得し、システムが保持してアプリ間で共有する。初回だけネットワークが要るため、取得できなければ `assets_unavailable` を返す。
3. Swift 版のバッチ文字起こしと同じ `SpeechTranscriber(locale:preset: .transcription)` を使う。確定結果（`isFinal`）だけを受け、時刻は結果の `range` から取る。
4. `.pcm` を数秒単位で読み、`SpeechAnalyzer.bestAvailableAudioFormat(compatibleWith:considering:)` の形式へ変換して `AnalyzerInput` の `AsyncStream` で渡す。ファイル全体をメモリに載せない。
5. `analyzeSequence` の後に `finalizeAndFinish(through:)` を呼ぶ。入力を閉じるだけでは結果のストリームは終わらない。
6. 解析の優先度は `SpeechAnalyzer.Options` で下げ、次の録音を妨げないようにする。

### Electron 側の扱い

- main process が実行する。引数は配列で渡し、シェルを経由しない。実行ファイルのパスはアプリ自身の場所から決め、renderer からは指定できない。
- 音源ごとに 1 つずつ順に実行する。同時に解析できる数にはシステムの上限があり、超えると失敗するためである。
- `done` を受け取り、終了コードが 0 のときだけ結果を採用する。両音源の segment を開始時刻順に並べ（同時刻は音源で順序を決める）、1 つの transaction でその録音の segment を置き換える。全文が成功するまで既存の文字起こしは置き換えない。
- 出力が 5 分間なければ止まったとみなしてプロセスを終了させ、失敗として表示する。Swift 版も同じ理由で停止検知を持っている。アプリ終了時と取り消し時もプロセスを終了させる。
- 録音停止後に自動で開始する。音声は成功後も消さない。失敗時は理由と「再試行」を表示する。`assets_unavailable` は「初回は言語モデルの取得にネットワークが必要」と案内する。
- 言語は設定で選ぶ（既定は日本語）。

### 権限

- ファイルの文字起こしは端末内で完結し、Swift 版も `SpeechAnalyzer` の利用時に音声認識の許可（`SFSpeechRecognizer.requestAuthorization`）を求めていない。Apple の許可手順は Apple のサーバーを使う認識が対象である。CLI からは許可を求めない。M0 で、許可なしにファイルを文字起こしできることを確かめた（ターミナルから実行）。
- 許可が必要だった場合、macOS は権限を「責任プロセス」である Electron アプリに帰属させる。利用目的の文言は CLI ではなくアプリの Info.plist に置く。

### 同梱と署名

- 置き場所は `Dahlia v2.app/Contents/MacOS/dahlia-transcribe`。Apple は実行ファイルを `Contents/MacOS`（または `Contents/Helpers`）に置くよう定めており、`Resources` に置くと署名と公証で問題が出る。Electron の `extraResources` や asar には入れない。
- 署名は内側から行う。CLI に識別子 `com.dahlia.desktop-v2.transcribe` と hardened runtime（`codesign -o runtime -i …`）を付けて署名し、その後にアプリ全体を署名する。CLI に entitlement は付けない。
- 開発時は `native/.build/release/dahlia-transcribe` をアプリの外から実行する。
- この Mac では ad-hoc 署名したアプリ内の実行ファイルが起動時に止まる事例があったが、ad-hoc 署名でパッケージ化した `Dahlia v2.app` の中の CLI は起動して結果を返した（2026-11-20）。署名 ID は `CODESIGN_IDENTITY` で選べる。

### テスト

- Node 側: 偽の CLI（JSON Lines を出すスクリプト）で、結果の採用条件、失敗 code の扱い、停止検知、並び替えと置き換えを確認する。
- Swift 側: 引数と PCM 読み取りの単体テスト。認識そのものはモデルが要るため、実録音での手動確認とする。

## 要約

- Pi を使わず、main process から AI Gateway を直接呼ぶ。`POST {workspace}/ai-gateway/anthropic/v1/messages`、既定モデルは `system.ai.claude-haiku-5-5`。対応するのは `claude-*` だけにし、API の形を 1 つに絞る。
- モデル一覧は `GET /api/2.1/unity-catalog/model-services?parent=schemas/system.ai` から `claude-*` を取り、設定で選べるようにする。
- プロンプトは [`AppSettings.swift`](../../apps/macos/Sources/Dahlia/Models/AppSettings.swift) の `defaultSummaryPrompt` から、スクリーンショットの規則を除いて移す。文字起こしは 1 つの `<transcript>` ブロックに `[HH:MM:SS] 音源: 本文` の形で入れる。文字起こしは信頼しない入力として扱う指示も移す。
- 出力は tool の入力 schema で JSON に固定する。`title`、`description`、`sections[]`（`heading` と `blocks[]`: `paragraph` / `bulleted_list` / `numbered_list` / `checklist` / `heading`、各 `transcript_ref`）、`action_items[]`。画像・表・コード・タグは持たない。
- 成功時は `summaries` を置き換え、空でない `title` と `description` を Meeting に反映する。利用者が名前を編集済みなら上書きしない。
- 要約スタイルは「標準」だけ。出力言語は設定で選ぶ（既定は日本語）。タイムアウトは 610 秒。

## 進め方

## 技術事項の確認状況（M0）

確認済み（2026-11-20）:

- **`node:sqlite`**: Electron 44.4.5（Node 24.21）で警告なしに使える。tsup は既定で `node:` 接頭辞を外すため、`removeNodeProtocol: false` にした。
- **CLI**: 許可なしで日本語の合成音声（8.4 秒）を 0.56 秒で文字起こしし、segment の開始・終了時刻が取れた。対応言語の一覧、非対応言語・引数誤り・1 サンプル未満の音声も想定どおりに返る。
- **同梱**: `Contents/MacOS` に置いて識別子と hardened runtime で署名した CLI が、ad-hoc 署名のアプリ内で起動した。パッケージ版アプリも起動する。

未確認:

1. **システム音声の取得**: Electron 44 の `audio: "loopback"`（CoreAudio Tap）が macOS 26 で音を取れるか。権限は責任プロセスに帰属するため、パッケージ版で確かめる。取れない場合、ScreenCaptureKit への自動切り替えはないので、CLI に ScreenCaptureKit での取得を持たせる。映像トラックを止めても音声トラックが続くかもあわせて確かめる。
2. **エコー**: スピーカー利用時に、相手の声がマイク側にも入って文字起こしが重複しないか。Chromium のエコー除去は他アプリの再生音を対象にしない可能性がある。Swift 版は DahliaAEC3 で除去している。現状は README の既知の制約とした。
3. **長時間の録音**: 1 時間の録音を停止せず最後まで文字起こしできるか。入力が途切れた区間（Chromium が無音ではなく入力なしを渡す場合）でマイクとシステム音声の時刻がずれないか。
4. **Gateway**: `claude-*` の Messages API で tool による JSON 出力が通るか。`all-apis` の token でモデル一覧と SCIM が取れるか。
5. **サインイン**: 実 Workspace でのサインイン、再起動後の refresh。

## 未解決事項

- 「先に決めてほしいこと」の 2（Tenet との不一致）の承認。1 と 3 は推奨案で実装した。
- 未確認の 1・2 の結果によっては、録音を Electron ではなく Swift 側に寄せる判断が要る。その場合は本計画の「録音」を書き直す。
- 配布（署名・公証・自動更新）と Swift 版からのデータ移行は、この計画の後に別途決める。
