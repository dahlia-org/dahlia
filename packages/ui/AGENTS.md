# Dahlia Shared UI Guide

## Scope

This file applies to `packages/ui` (`@dahlia-ai/ui`), the private source package for the Web UI shared by Dahlia Server's Private Web and other renderers. The repository-root `AGENTS.md` still applies. Dependency ownership and package boundaries follow [pnpm workspace と共通 UI の依存管理](../../docs/adr/monorepo/dependencies.md).

## Layout

- `components/`: generic UI parts (`components/ui` holds the shadcn/ui New York primitives). `layout/`: page shell. `lib/` and `styles.css`: utilities and Tailwind styles.
- `screens/`: Dahlia screens. Keep form drafts, open state and focus inside the screen; move data access, transactions, subscriptions and AI calls to `api/` or existing hooks.
- `App.tsx` and `app/`: startup, session, routing and in-app navigation. `index.ts` lists the public exports re-exported by `@dahlia-ai/server/client`; add names deliberately and keep existing names and types compatible.
- `api/`: the generated OpenAPI client (`generated-*.ts`, regenerated by `pnpm openapi:generate` in `apps/server`; never edit), live-data, SSE notifications and transaction handling.
- `documents/`: the runtime-independent Documents core and editor shared with Server and the macOS app ([Documents ADR](../../docs/adr/shared/documents.md)). `model/`: browser-safe wire models reused by Server.

## Boundaries

- Never import Server or Desktop runtime code, databases, secrets or Node-only modules. Server and Desktop depend on this package, never the reverse.
- Use OpenAPI generated types for Dahlia API data; do not add hand-written DTOs. Reuse live-data, `commitSyncTransaction` and the Documents core instead of new transports or sync paths.
- Express host differences (API origin, sign-in, shared-link origin, AI execution location) as small `App` props or functions. Do not add environment-wide interfaces, DI containers or per-screen host branches.
- After changing `documents/`, run `pnpm --filter @dahlia-ai/ui documents:build` and commit the regenerated macOS resources.

## Validation

```bash
pnpm --filter @dahlia-ai/ui check   # Documents assets, lint, types and UI tests
cd apps/server && pnpm check        # Server bundles this package; run for shared changes
```

Web browser regression fixtures remain in `apps/server/tests/browser` and run on the Server's Vite origin (`pnpm dev:client`).
